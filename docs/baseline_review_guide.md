# Baseline human review guide

Use `evaluation/gold_v1.jsonl` (verify its checksum) and `reports/baseline_v1_runs.jsonl`. This is a closed-book single-prompt baseline: the model receives the question and any explicit preceding user turn, not gold answers, citations or retrieved PDF text. Reviewers should compare each response with its frozen gold conditions and check the cited original page when needed. FAQ assertions must be attributed to the relevant dated FAQ; a dated document alone cannot establish current legal applicability. Some cases admit uncertainty when source text was not provided, but do not score an unsupported substantive claim as correct.

Enter `1` or `0` in `correct` only after reviewing all conditions; leave blank if undecidable. Enter refusal correctness only for cases that explicitly require refusal or abstention; otherwise leave blank (not applicable). Record one primary failure category such as hallucination, reasoning error, format error, or evidence unavailable; retrieval and tool failures cannot be attributed to tools that were not present. Do not mark the contents correct merely because JSON parses. Note unclear gold answers separately and resolve using a future version rather than silently editing v1. Independent review by two team members and discussion of disagreements is recommended. Never enter personal data or secrets in the review.

Schema validity is mechanical, whereas accuracy, refusal correctness and qualitative examples require review. Failed API calls count as incomplete, not factually incorrect. Cost remains unknown unless a real rate is supplied. The multi-turn cases supply an earlier user message but no prior assistant response; they test reference resolution, not durable server state.
