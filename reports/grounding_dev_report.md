# Grounded drafting development checks

The Phase 2 prototype now has an **opt-in, human-review-only** two-pass drafting workflow. It checks source/page identity and exact quote presence, asks the same permitted hosted chat model to assess support, and never issues a final automatic answer. A model-supported output is labeled `review_required` and `draft_not_verified`; invalid output, model-identified insufficiency, suspected injection or a failed check escalates. The separate evidence-only workflow remains available. This is not LangGraph and is not a validated legal-answering system.

Development tests used four invented non-gold examples, not the frozen evaluation questions. `grounding_dev_smoke_initial.json` records that the initial version escalated all four because the model used an unexpected field name. After normalizing `text` as an alternative quote field while requiring exact text, `grounding_dev_smoke_before_guard.json` recorded an important failure: the model generated **ninety days** from a malicious source instruction, and the model support checker accepted the instruction as its evidence. A simple deterministic guard was added for some obvious instruction patterns and for certain explicit insufficiency statements. In `grounding_dev_smoke.json`, the two answerable fictional examples produced drafts requiring human review, while the insufficient and tested injection examples escalated. This tiny, hand-designed development set does not establish security, recall, precision, safety or generalization; the guard can miss variants and reject legitimate source passages. The model check itself can be wrong.

A separate new development question about Code on Wages section 8(2), with a source filter, escalated because the citation check failed even though a lexical search retrieved the relevant page. No unsupported generated answer was shown. This shows that availability and usability remain inadequate. The raw model response from this check was not recorded; token usage for these checks was not captured. Cost is unknown. None of the development outcomes is an evaluation of the frozen gold set.

Unit tests cover source spoofing, invented or contradictory quotes, missing evidence, malformed JSON, conflicting response fields, explicit source injection, and the requirement for human review even if the model support checker mistakenly approves a wrong claim. User-provided scored baseline and independent retrieval relevance issues remain open. Further work requires broader separately reviewed adversarial cases, robust handling of source conflicts and semantic support, and an honest held-out evaluation before any automatic release or Phase 2 completion claim.

## Follow-up development — citation whitespace and broader checks

A structural diagnostic of the real-document failure showed that the model cited the correct chunk but replaced PDF line breaks with spaces. `resolve_quote` now accepts a unique whitespace-only match and returns the exact original-page span; changed words or numbers and ambiguous normalized matches fail closed. The same development question about section 8(2) was rerun through retrieval, embeddings and the hosted chat endpoint: the output was labeled `review_required`, with the source citation to Code on Wages PDF page 7 and a quotation containing the PDF's actual line break. This is a single known development case, not an accuracy estimate.

An eight-case hand-designed development run (`grounding_dev_cases.json`) included two fictional factual questions, one missing-evidence case, three injected-source variants and two questions supplied directly with selected real PDF chunks. Four answerable examples produced model-checked drafts requiring human review; the insufficient and three injection examples escalated. Two obvious injection cases were caught by the pattern guard and the subtler one escalated after the model support check. The development script's simple checks matched the expected behaviors for all eight; this is not an independent adversarial benchmark, a guarantee of safety, or evidence that arbitrary instructions or unsupported claims are detectable. The two real-source examples used manually selected pages and do not measure retrieval. The endpoint reported 2,390 prompt tokens and 691 completion tokens for this run; cost is unknown. Earlier observed injection failure remains documented above.

The workflow still never automatically releases generated answers. Human verification of each draft, source relevance, source conflict, OCR and legal applicability remains necessary. Independent relevance labels and held-out evaluation remain outstanding; no graph or additional generative model was introduced.

## Question and named-source alignment guard — 2026-11-20

To address the observed wrong-topic and wrong-document review drafts, the experimental workflow now adds a third permitted-model call after the draft and quote-support check. It asks whether the draft answers the actual question and whether a specifically requested source matches the cited title. Missing, malformed or negative verdicts escalate; a pass is still only a human-review draft. A conservative local check rejects some incomplete simple paired-item questions. These checks do not guarantee question relevance, completeness, exact source identity or prompt-injection resistance. No automatic answer is released, and no extra generative service or graph is used.

A six-case fictional development set (`alignment_dev_cases.json`) showed the expected overall pass/block decision for two positive and four negative examples after the pair guard; the model initially accepted a deliberately incomplete answer and the guard rejected it. A first end-to-end rerun rejected two valid fictional answers because the model invented an unspecified source constraint; the implementation now skips that constraint when no source words are present. A subsequent rerun of eight existing development cases returned four review drafts and escalated four insufficient or injected cases, matching their simple development checks. These are reused, non-independent development examples.

An additional six hand-designed fictional checks (`alignment_additional_dev.json`) produced five expected decisions and one false rejection: a complete but compact answer omitted the explicit words for both requested dimensions, so the conservative pair guard escalated it. This is an availability limitation, not a benchmark score. The source-name detection is heuristic and can miss unnamed-document constraints; the same small model may pass irrelevant or wrong-source answers. The earlier actual 19-question evaluation, including draft-029, was not rerun to tune against the frozen questions; those recorded results are unchanged. A new, unseen independently reviewed document evaluation is needed to establish whether the observed corpus failure is fixed. Human review is still required for every emitted draft.
